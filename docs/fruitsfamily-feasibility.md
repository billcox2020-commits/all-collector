# 번개장터 → 후루츠패밀리: 조사 및 1개 상품 준비

확인일: 2026-11-13. 기준 코드: main `f04334ae656bf136d4fb9430628eb70aeb84550a`.

사용자가 구체화한 우선 범위는 사진·상품명·가격을 옮기고, 브랜드·카테고리·사이즈는 가능한 저장값을 쓰며 설명은 직접 보완하는 것이다. 사진만으로 등록할 수 있다고 가정하지 않는다. 공식 가져오기에서 사진만 선택하거나 미등록 초안으로 저장하는 옵션은 확인하지 못했다.

## 결론

번개장터 상점 상품을 후루츠로 가져오는 **공식 기능은 있다**. 우선 선택할 경로는 후루츠 앱의 ‘타 플랫폼에서 상품 가져오기’다. 별도 개발 없이 사용할 수 있지만, 한 번 복사하는 기능이며 지속 동기화가 아니다. 이 작업에서는 로그인·가져오기·상품 등록을 실행하지 않았다.

| 기능 | 확인 결과 |
|---|---|
| 공식 상점 가져오기 | 본인인증·정산계좌 완료 계정, 계정당 1회, 최근 등록순 판매 중 상품 최대 500개. 원본 샵 지원·해당 계정의 사용 가능 여부는 신청 화면에서 확인 필요 |
| 가져오기 후 동기화 | 원본 추가·가격 수정·삭제·판매완료를 후루츠에 반영하지 않음 |
| 최초 1개 시험 | 공식 가져오기에서 1개 선택 기능은 확인 못함. 시작 후 취소 불가, 사전 확인 없이 즉시 또는 순차 공개 가능. 이 경로로 시험하지 않음 |
| PC 상품 등록 | 사업자등록증 보유 전문 판매자 대상. `/upload`에서 로그인 후 이용. 개인 계정 자격은 미확인 |
| 웹 수정·삭제·판매완료 | 공식 PC 도움말상 미지원. 앱에서 처리 |
| 공개 개발자 API·CSV/Excel 대량 등록 | 확인한 공식 사이트·고객센터·검색에서 문서나 발급 절차를 찾지 못함. 존재하지 않는다고 단정하지 않음 |
| 외부 도구 자동 등록 허용 | 공식 허용 범위 미확인. 플랫폼 자체 가져오기 권한을 외부 봇 허용으로 해석할 수 없음. 실제 연결 전 고객센터에 API/파트너 연동·자동화 허용 여부 확인 필요 |
| 관리자 연동 | 정적 GitHub Pages이므로 로컬 변환·검토·다운로드 가능. 비밀키를 안전하게 보관하는 서버는 현재 없음 |

## 실제 코드와 저장 자료

- `.github/workflows/bunjang-direct-sync-20261104.yml`: 요청 파일 변경 또는 수동 실행으로 일반 Chromium 수집 → 기존 Python 병합 → 신규 자료만 커밋. 이번 작업은 새 수집을 요청하지 않았다.
- `scripts/fetch_bunjang_public.mjs`: 상점 `4934829` 공개 목록을 세 번 스크롤하고, 화면에 보이는 ID와 판매 상태·원본 날짜를 확인한다. 전체 재고 수집을 보장하지 않는다.
- `scripts/bunjang-public-records.mjs`: 대표 사진과 있으면 설명을 정규화하나 사이즈와 사진 갤러리는 전달하지 않는다.
- `scripts/sync_bunjang.py`: 기존 ID는 갱신하지 않는 추가 전용 병합. 원본 판매완료·가격 변화를 현재 목록에 반영하는 재고 동기화 기능이 아니다.
- `data/bunjang-active.json`: 452개. 사이즈 220개 기재·232개 미기재. 452개 모두 설명이 수집 안내문. 갤러리 없음. 확인일은 420개가 9월 20일, 23개가 11월 4일, 이후 9개. 현재 판매 중임을 보증할 수 없다.
- `data/fruitsfamily.json`: `bnr34korea` 계정의 9월 16일 부분 목록 29개. raw pool은 38개. 두 파일은 `items`가 아닌 `records` 형식이다. 교집합을 제거해 참고 목록으로 사용한다. 계정 수정 이전 legacy 파일은 잘못된 계정 혼합 가능성 때문에 대조 대상에서 제외했다.
- `admin/admin.js`: 개인 기록·번개장터 목록·별도 관리자 override를 합쳐 편집한다. GitHub 토큰은 세션에 두고 선택적으로 기기 내 암호화 vault에 저장한다. 후루츠 인증 저장 기능은 없다.

기존 데이터는 원본 설명·전체 사진·실시간 재고가 부족하다. 직접 가져오기가 지원되는 계정이면 원본 상점에서 공식 가져오기를 하는 편이 적합하다. 가져오기 후에도 상품 정보·중복·판매 조건을 확인해야 한다.

## 이번 개발 범위

`admin/fruitsfamily.html`에 별도 준비 화면을 추가하고 기존 관리자 상단에 링크 1개를 추가했다. 기존 편집 코드·수집기·워크플로·데이터는 수정하지 않는다.

1. 번개장터 상품 중 숨김·판매완료·예약 항목을 제외하고 관리자 override를 반영한다.
2. 사용자가 선택한 1개만 상품명·정수 원화 가격·사진 주소·실제 설명·브랜드/분류/사이즈 참고값으로 변환한다. 공식 API payload나 업로드 양식을 가장하지 않는다.
3. 수집 안내문은 판매 설명에서 제외한다. 사진은 순서와 갤러리를 보존하며 10장 초과는 잘라내지 않고 경고한다. 사진 다운로드·용량 검증은 미실행이다.
4. 기존 후루츠 목록에서 ID 연결·정규화 상품명·사진 주소·유사 상품명으로 중복 후보를 표시한다. 가격 변경·판매완료도 중복 후보에서 제외하지 않는다. 부분 목록에서 후보가 없어도 등록 가능으로 판정하지 않는다.
5. 상품 상태·배송·수수료는 추측하지 않고 미설정으로 둔다. 실제 등록 화면의 브랜드·세부 카테고리·사이즈 선택값을 확인해야 한다.
6. 1개 검토용 JSON을 내려받을 수 있다. 후루츠 요청, 자동 등록 버튼, 승인 토큰, 비밀번호 입력·저장은 없다. 화면은 공개 저장 자료만 읽고 세션 토큰도 읽지 않는다.

검토 파일은 사진 파일을 포함하지 않으며 공식 CSV/Excel 가져오기 파일이 아니다. 알려진 목록만으로 중복을 완전 방지할 수 없으므로 실제 전송은 구현하지 않았다. 지속 동기화가 필요하다면 공식 연동 권한 확보 후 서버 측 비밀 관리, 최신 전체 상품 대조, 영속 ID 매핑, 동시 등록 잠금, 타임아웃 결과 재조회, 사용자 승인 기록이 필요하다.

## 1개 테스트 및 사용

`node --test tests/*.test.mjs`로 기존 수집 테스트와 새 준비 테스트를 실행한다. 새 테스트 중 실제 저장 상품 `BJ-447097552` 1개를 변환하여 설명·사이즈 누락과 전송 불가를 확인한다. 나머지는 경계조건용 가상 입력이다. 상품을 등록하는 테스트는 없다.

검증 결과: 새 단위 테스트 7개·기존 수집 테스트 2개 통과. 설치된 Chromium으로 로컬 준비 화면에서 해당 상품 선택·초안 표시·JSON 다운로드를 확인했다. 준비 대상 452개, 후루츠 참고 목록은 중복 ID 제거 후 42개다. 브라우저 오류·쓰기 요청·외부 요청은 없었다. 선택 변경 시 이전 초안도 숨겨진다. 기존 `data/` 파일과 수집·편집 스크립트는 git 기준 변경 없음.

저장소 루트에서 `python -m http.server 8000` 실행 후 `/admin/fruitsfamily.html`을 열고 상품 1개 선택 → ‘1개 초안 확인’ → 검토 파일 다운로드. 기존 GitHub 관리자 로그인은 필요 없다. 공개 자료를 다루는 준비 화면이며 인증을 제공하는 화면은 아니다.

실제 첫 등록 전에는 현재 후루츠 전체 상품과 대조하고, 정확한 사진·설명·판매 조건이 갖춰진 1개 초안을 사용자에게 제시해 승인을 받아야 한다. 공식 상점 가져오기는 다수 상품이 공개될 수 있으므로 별도의 실행 범위 승인이 필요하다.

## 공식 근거

공식 도움말 본문을 공개 HTTP GET으로 확인했다. 검색 도구의 일부 캐시는 예전 내용이어서 최신 본문을 우선했다. 실제 후루츠 판매/업로드 화면의 로그인 계정 검증은 하지 않았다. `/sell` 공개 GET은 HTTP 403이므로 화면 지원을 직접 검증했다고 주장하지 않는다.

- [상점 가져오기 안내](https://intercom.help/fruits-family-co/ko/articles/17028585) — 1회·500개·비연동·계정 조건.
- [상품 가져오기 약관](https://intercom.help/fruits-family-co/ko/articles/16780883) — 공개 시작, 취소 불가, 일부 실패·이용 횟수, 일회성 복사.
- [PC 등록·판매 관리](https://intercom.help/fruits-family-co/ko/articles/11977919) — 전문 판매자 자격 및 앱 전용 관리 기능.
- [상품 등록 방법](https://intercom.help/fruits-family-co/ko/articles/10574948) — 사진 최대 10장, 정보·상태·배송·수수료.
- [가격 기준](https://intercom.help/fruits-family-co/ko/articles/16862791) — 최소 5천 원, 1천만 원 이상 고객센터 경로.
- [사진 용량](https://intercom.help/fruits-family-co/ko/articles/16863135) — 전체 합계 100MB.
- [업로드·중복 기준](https://intercom.help/fruits-family-co/ko/articles/16862790) — 중복 게시 제한.
- [이용약관](https://intercom.help/fruits-family-co/articles/3683933), [상품 등록 운영 정책](https://intercom.help/fruits-family-co/ko/articles/12049796) — 무단 역설계·정보 수집 등 제한 및 상품 고지 기준. 확인한 문구만으로 자체 자동 등록 허용 여부는 판단할 수 없다.
